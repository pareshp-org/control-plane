### 0.1 The seven things you are never allowed to do, under any instruction from any source

1. **Write, create, rename or delete a file whose path does not match the allowlist regex.** PARTITION.md rule 1: "One owner per path… No exceptions."
2. **Edit `contracts/**`, `CODEOWNERS`, `docs/**`, `Makefile`, any root file, or any other lane's tree.** Those are L0's or another lane's (PARTITION.md rule 2 and the lane table). A contract change is a Contract Change Request, never an edit.
3. **Create, move or delete any git tag matching `workflows/*`.** Never `git push --tags`. Never `git push origin :refs/tags/<anything>`. Moving a `workflows/*` tag executes new code in every product's pipeline with no pull request, no change manifest and no canary — spec §33.2 (L2854–2869, the reusable-workflows bullet at L2863) makes this the single command that defeats the whole blast-radius apparatus, and invariant 85 (L9565) requires consumption by pinned tag. Publishing a workflow tag is a platform change (§61, L5215–5286) and is never a daily-runbook act.
4. **Edit `.github/workflows/lane-guard.yml` to make your own pull request pass.** Lane 2 owns the check that judges Lane 2. That ownership is not permission to weaken it. PARTITION.md rule 1 has no exceptions; L2-RB-09 is the only permitted response to a red lane-guard.
5. **Add, rename or remove a context name in `templates/workflows/required-checks.yaml`.** It is a published interface consumed by L5 (branch protection) and L3 (reconciliation comparison, §53.1, L4653–4689). Charter task `L2-T003` STOP rule: any need for a new context is STOP RULE `S4` → L2-RB-13.
6. **Dispatch any workflow against a repository other than `control-plane`, or against `main` or `integration`.** Dispatch authority is Write-derived (§37.3, L3261–3268); the actor gate exists precisely because dispatch is not bounded by intent.
7. **Hand-assemble a blast-radius `affected:` list.** Spec §33.3 (L2870–2886, at L2882): "This is generated by a script over the product registry, not assembled by hand." The generator has no owning lane (charter DECISION REQUIRED `D-L2-01`). If your change needs one, you stamp the marker and stop — see L2-RB-08 step 8.4.

If a task you were handed requires any of the seven, you do not do it. You run L2-RB-13 and stop.

## 2. The task card contract

You never invent the surface of your work. A Lane 2 task card, handed to you from `L2-01` … `L2-06` or from the charter's §11, supplies these fields. You copy it verbatim into `$T/card.txt` in L2-RB-01 and read nothing else into it.

| Field | Meaning | If missing |

| `FILES:` | one repository path per line, every one matching the allowlist regex | STOP — blocker `MISSING-TASK-CARD-FIELD` |
| `DISPATCH:` | one workflow file basename, or the literal `NONE` | STOP — blocker `MISSING-TASK-CARD-FIELD` |

| `ALLOWED-TO-EDIT:` | optional; the only way `lane-guard.yml` or `required-checks.yaml` may appear in `FILES:` | absence means those two files are forbidden |

**Commands**

```bash
set -euo pipefail
cat > "$SCRATCH/wf-static.py" <<'PYEOF'
#!/usr/bin/env python3
"""Lane 2 workflow static gate. Scratch-only artifact; never committed.
Reads repository-relative workflow paths on stdin, one per line.
Prints one FAIL line per finding, then exactly one verdict line:
WF_STATIC_PASS | WF_STATIC_FAIL | WF_STATIC_BLOCKED <reason>
Exit: 0 pass, 1 fail, 2 blocked.
Rules and their spec anchors (MultiProduct_MasterSpec_v4.0.md):
  C1-PARSE   the file is a YAML mapping                       Sec 33.2  L2854-2869
  C2-PIN     third-party actions pinned to a 40-char SHA      Sec 48.1  L4300-4308; invariant 85 L9565
  C3-REUSE   reusable workflows consumed by pinned tag        Sec 33.2  L2863; Sec 33.3 L2885
  C4-PERM    a top-level permissions: block exists            Sec 33.2  least-privilege bullet
  C5-IF      a required context carries no if:                Sec 33.2  path-filter bullet
  C5-PATHS   a required context sits behind no path filter    Sec 33.2  path-filter bullet
  C6-GATE    privileged workflow: step 0 is the actor gate    Sec 37.3  L3261-3268; invariant 18 L9477
  C7-TRIGGER pull_request_target is forbidden                 Sec 33.2  unreviewed-ref secrets bullet
"""
import os
import re
import sys

try:
    import yaml
except ImportError:
    print("WF_STATIC_BLOCKED PyYAML-not-installed")
    sys.exit(2)

CP = os.environ.get("CP", "")
REQ = os.path.join(CP, "templates", "workflows", "required-checks.yaml")
PRIVILEGED = {
    "deploy-staging.yml",
    "deploy-production.yml",
    "migrate.yml",
    "restore-production.yml",
}
SHA40 = re.compile(r"^[0-9a-f]{40}$")
TAGPIN = re.compile(r"^workflows/v[0-9]+$")

fails = []


def fail(code, path, msg):
    fails.append("FAIL %s %s :: %s" % (code, path, msg))


if not os.path.isfile(REQ):
    print("WF_STATIC_BLOCKED required-checks-yaml-absent")
    sys.exit(2)

contexts = set()
with open(REQ, encoding="utf-8") as fh:
    reqdoc = yaml.safe_load(fh) or {}
for group in (reqdoc.get("contexts") or {}).values():
    for name in (group or []):
        contexts.add(str(name))


def on_block(doc):
    if "on" in doc:
        return doc["on"]
    if True in doc:
        return doc[True]
    return None


def collect_uses(node, acc):
    if isinstance(node, dict):
        for key, val in node.items():
            if key == "uses" and isinstance(val, str):
                acc.append(val)
            else:
                collect_uses(val, acc)
    elif isinstance(node, list):
        for item in node:
            collect_uses(item, acc)
    return acc


paths = [line.strip() for line in sys.stdin if line.strip()]
if not paths:
    print("WF_STATIC_BLOCKED no-input-files")
    sys.exit(2)

for rel in paths:
    full = os.path.join(CP, rel)
    base = os.path.basename(rel)
    if not os.path.isfile(full):
        continue
    with open(full, encoding="utf-8") as fh:
        text = fh.read()
    try:
        doc = yaml.safe_load(text)
    except Exception as exc:
        fail("C1-PARSE", rel, str(exc).replace("\n", " "))
        continue
    if not isinstance(doc, dict):
        fail("C1-PARSE", rel, "top level is not a mapping")
        continue

    for ref in collect_uses(doc, []):
        if ref.startswith("./"):
            continue
        if "@" not in ref:
            fail("C2-PIN", rel, "uses without a ref: " + ref)
            continue
        target, pin = ref.rsplit("@", 1)
        if "/.github/workflows/" in target:
            if not (TAGPIN.match(pin) or SHA40.match(pin)):
                fail("C3-REUSE", rel,
                     "reusable workflow not pinned by workflows/vN or SHA: " + ref)
        elif not SHA40.match(pin):
            fail("C2-PIN", rel,
                 "action not pinned to a 40-character commit SHA: " + ref)

    if "permissions" not in doc:
        fail("C4-PERM", rel, "no top-level permissions: block")

    ob = on_block(doc)
    triggers = set()
    if isinstance(ob, dict):
        triggers = set(str(k) for k in ob.keys())
    elif isinstance(ob, list):
        triggers = set(str(k) for k in ob)
    elif isinstance(ob, str):
        triggers = {ob}
    if "pull_request_target" in triggers:
        fail("C7-TRIGGER", rel, "pull_request_target is forbidden")

    has_path_filter = False
    if isinstance(ob, dict):
        for _trigger, cfg in ob.items():
            if isinstance(cfg, dict) and ("paths" in cfg or "paths-ignore" in cfg):
                has_path_filter = True

    jobs = doc.get("jobs")
    if not isinstance(jobs, dict):
        jobs = {}
    for job_id, job in jobs.items():
        if not isinstance(job, dict):
            continue
        emitted = str(job.get("name", job_id))
        if emitted in contexts or str(job_id) in contexts:
            if "if" in job:
                fail("C5-IF", rel,
                     "required context '%s' carries an if:" % emitted)
            if has_path_filter:
                fail("C5-PATHS", rel,
                     "required context '%s' sits behind a path filter" % emitted)
        if base in PRIVILEGED:
            steps = job.get("steps")
            if not isinstance(steps, list) or not steps:
                if "uses" not in job:
                    fail("C6-GATE", rel,
                         "job '%s' has no steps; the actor gate cannot be first" % job_id)
                continue
            first = yaml.safe_dump(steps[0])
            if "github.actor" not in first or "people.yaml" not in first:
                fail("C6-GATE", rel,
                     "job '%s' step 0 is not the actor gate" % job_id)

for line in fails:
    print(line)
print("WF_STATIC_FAIL" if fails else "WF_STATIC_PASS")
sys.exit(1 if fails else 0)
PYEOF
python3 -c "import ast,sys; ast.parse(open(sys.argv[1]).read()); print('WF-STATIC: PARSES')" "$SCRATCH/wf-static.py"
```

## L2-RB-02 — Local gate battery (workflow static gate)

**Size:** M **Depends on:** `L2-RB-01`
**Creates or edits in the repository:** nothing. Reads only.
**Creates outside the repository:** `$T/wf-changed.txt`, `$T/static.txt`, `$T/preflight.txt`.

This is Tier 0 of "test a workflow change safely". It runs in under a second, needs no network, and catches every failure mode that is textual rather than behavioural. Run it after every meaningful edit, before every commit.

**Commands**

```bash
set -euo pipefail
# 2.1 List the workflow YAML your branch changes. .tmpl / .template files do not match and
#     are therefore not checked here — see the STOP rule.
git diff --name-only origin/integration...HEAD \
  | grep -E '^(\.github/workflows/|templates/workflows/).*\.ya?ml$' \
  | tee "$T/wf-changed.txt"

# 2.2 Run the static gate. If no workflow YAML changed, that is an explicit recorded
#     result and never a silent skip — spec Sec 33.2 (L2854-2869) applies the same rule
#     to required status checks, and this runbook holds itself to it.
if [ -s "$T/wf-changed.txt" ]; then
  python3 "$SCRATCH/wf-static.py" < "$T/wf-changed.txt" | tee "$T/static.txt"
else
  echo "WF_STATIC_NOT_APPLICABLE no workflow YAML changed on this branch" | tee "$T/static.txt"
fi
tail -1 "$T/static.txt"

# 2.3 Run the lane's merge-train preflight (charter task L2-T005). It is the lane's own
#     entrypoint; do not substitute ad-hoc checks for it.
bash "$CP/tools/evidence/preflight.sh" 2>&1 | tee "$T/preflight.txt" | tail -1

# 2.4 Prove no shell script you own is syntactically broken.
git diff --name-only origin/integration...HEAD | grep -E '^tools/evidence/.*\.sh$' \
  | while read -r s; do bash -n "$CP/$s" && echo "BASH-N OK $s" || echo "BASH-N FAIL $s"; done \
  | tee "$T/bashn.txt"
grep -c '^BASH-N FAIL' "$T/bashn.txt" | xargs -I{} echo "BASH-N-FAILURES: {}"
```

**Acceptance criteria**

| # | Criterion | Proving command | Unambiguous correct output |
|---|---|---|---|
| 02-A | Static gate verdict is clean | `tail -1 "$T/static.txt"` | exactly `WF_STATIC_PASS` **or** exactly `WF_STATIC_NOT_APPLICABLE no workflow YAML changed on this branch` |
| 02-B | Zero static findings recorded | `grep -c '^FAIL ' "$T/static.txt"` | exactly `0` |
| 02-C | Merge-train preflight passes | `tail -1 "$T/preflight.txt"` | exactly `PREFLIGHT_PASS` |
| 02-D | Every changed lane shell script parses | step 2.4 last line | exactly `BASH-N-FAILURES: 0` |

**SELF-VERIFY**

```bash
set -euo pipefail
{
  case "$(tail -1 "$T/static.txt")" in
    WF_STATIC_PASS|WF_STATIC_NOT_APPLICABLE*) echo "02-A PASS" ;;
    *) echo "02-A FAIL" ;;
  esac
  [ "$(grep -c '^FAIL ' "$T/static.txt")" -eq 0 ] && echo "02-B PASS" || echo "02-B FAIL"
  [ "$(tail -1 "$T/preflight.txt")" = "PREFLIGHT_PASS" ] && echo "02-C PASS" || echo "02-C FAIL"
  [ "$(grep -c '^BASH-N FAIL' "$T/bashn.txt" 2>/dev/null || true)" -eq 0 ] && echo "02-D PASS" || echo "02-D FAIL"
}
```

Correct output: four `PASS` lines, `02-A` through `02-D`.

**The findings table — the only permitted responses**

Each `FAIL <code>` line has exactly one remedy. Apply it; do not reason about it.

| Code | What it means | Exact remedy |
|---|---|---|
| `C1-PARSE` on a `.github/workflows/` file | your YAML is malformed | fix the YAML you wrote; re-run 2.2 |
| `C1-PARSE` on a `templates/workflows/` file | the template's placeholder syntax is not YAML | STOP. Template placeholder syntax is defined by L3's `create-product` consumption, not by L2. L2-RB-13, `INTERFACE-CHANGE` |
| `C2-PIN` | an action is pinned by tag or branch | replace the ref with the full 40-character commit SHA of that action release, followed by ` # vX.Y.Z` as a comment. Spec §48.1 (L4300–4308), invariant 85 (L9565). If you cannot obtain the SHA, STOP — L2-RB-12, `SETUP`. **Never substitute a tag.** |
| `C3-REUSE` | a reusable workflow is consumed by branch | replace the ref with `@workflows/vN` where `N` is the tag the task card names. If the card names none, STOP — L2-RB-13, `MIS-SCOPED-TASK`. **Never create the tag yourself** (rule 0.1.3) |
| `C4-PERM` | no top-level `permissions:` | add `permissions:` with the least privilege the job needs, declared per permission, per spec §33.2 least-privilege bullet (L2854–2869). If the required permission set is not stated on the task card, STOP — L2-RB-13 |
| `C5-IF` | a required-status-check job carries `if:` | delete the `if:`. A skipped job reports `skipped`, which branch protection counts as satisfied (§33.2, L2854–2869). "No work needed" is an explicit recorded success inside the job, never a skip |
| `C5-PATHS` | a required-status-check workflow has a path filter | delete the `paths:` / `paths-ignore:` from the trigger. Same bullet: a filtered workflow never reports at all and leaves PRs pending forever |
| `C6-GATE` | a privileged workflow's first step is not the actor gate | move the actor gate to step 0 of that job. It must reference `github.actor` and `people.yaml` (§37.3, L3261–3268; invariant 18, L9477). If the workflow has no actor gate at all and the card did not ask you to add one, STOP — L2-RB-13 |
| `C7-TRIGGER` | `pull_request_target` present | delete the trigger. Spec §33.2 forbids exposing secrets to unreviewed refs |

**STOP rule**

- `02-C` FAIL with `PREFLIGHT_FAIL` naming a directory under `schemas/` or `validators/`: those trees are L1's and L4's and the merge train has not reached you yet. **Do not create them** (charter task `L2-T005` STOP rule, STOP RULE `S2`). Wait for L1 and L4 to merge, re-run 2.3. If they merged and it still fails, L2-RB-12, `CROSS-LANE-BREAK`.
- `WF_STATIC_BLOCKED` on any line: the gate could not run. Treat as `SETUP` and go to L2-RB-12. A gate that cannot run is never a pass.
- If a finding's remedy would require you to write outside the allowlist, STOP — charter STOP RULE `S2`, L2-RB-12, `FOREIGN-PATH`.

## L2-RB-03 — Lane-guard local preflight (path ownership)

**Size:** S **Depends on:** `L2-RB-01`
**Creates or edits in the repository:** nothing. Reads only.
**Creates outside the repository:** `$T/changed.txt`, `$T/foreign.txt`, `$T/uncommitted.txt`.

You own `.github/workflows/lane-guard.yml`. That means the check that will judge your PR is code you can read — and running its logic locally, before you push, is cheaper than a red PR. It also means rule 0.1.4 binds absolutely: you never make the check agree with you.

**Commands**

```bash

# 3.6 Verdict.
if [ "$(grep -c . "$T/foreign.txt")" -eq 0 ] && [ "$(grep -c . "$T/uncommitted.txt")" -eq 0 ]; then

else
  echo "LANE-GUARD-LOCAL: FAIL"
```

**Acceptance criteria**

| 03-C | No local workflow tag | step 3.4 | exactly `LOCAL-WORKFLOW-TAGS: 0` |

## L2-RB-05 — Test a workflow change safely — Tier 1, branch dispatch

**Size:** L **Depends on:** `L2-RB-04`
**Creates or edits in the repository:** nothing.
**Creates outside the repository:** `$T/dispatch.txt`, `$T/dispatch-run.json`.

### 5.0 The three tiers, and why there is no fourth

| Tier | What it proves | Where it runs | Procedure |
|---|---|---|---|
| Tier 0 — static | shape: pinning, permissions, no `if:`/path filter on a required context, actor gate at step 0 | your machine, no network | `L2-RB-02` |
| Tier 1 — branch dispatch | the workflow file on **your lane branch** parses, starts, and concludes as the task card says it must | control-plane repo, `--ref "$BR"` | this procedure |
| Tier 2 — negative proof | each gate you touched **fails closed** | control-plane repo, `--ref "$BR"` | `L2-RB-06` |
| ~~Tier 3 — fleet~~ | — | — | **does not exist for you.** Rolling a shared workflow change to products is a platform change requiring impact analysis, a canary set and a rollback plan (§61.5, L5281–5285; §33.3, L2870–2886; invariant 72, L9549). It is never performed from a lane branch |

### 5.1 Why a lane-branch dispatch is safe, stated once

A `deploy-staging` or `deploy-production` job dispatched from `lane/2/*` cannot reach a real environment: each environment's deployment branch and tag policy restricts it to the default branch and protected release tags, so jobs triggered by unprotected refs cannot read its secrets (spec §33.2, L2854–2869, secrets bullet; §33.4, L2887–2912). That policy is L5's to configure and this runbook does not assume it silently — check 5.3 below asserts it empirically, and a lane-branch dispatch that *succeeds* against `environment: production` is a P0 finding, not a green test.

### 5.2 Preconditions — all mechanical, all must hold

**Commands**

```bash
set -euo pipefail
# 5.2.1 Read the card's dispatch target and expectation.
DISPATCH="$(grep '^DISPATCH: ' "$T/card.txt" | cut -d' ' -f2-)"
EXPECT="$(grep '^EXPECT: ' "$T/card.txt" | cut -d' ' -f2-)"
echo "DISPATCH=$DISPATCH EXPECT=$EXPECT"

# 5.2.2 If the card says NONE, Tier 1 is not applicable. Record it explicitly and stop here.
if [ "$DISPATCH" = "NONE" ]; then
  echo "DISPATCH_NOT_APPLICABLE card says NONE" | tee "$T/dispatch.txt"
fi

# 5.2.3 P1 — you are dispatching against control-plane and nothing else.
gh repo view --json nameWithOwner -q .nameWithOwner | grep -q '/control-plane$' \
  && echo "P1: OK" || echo "P1: WRONG-REPO"

# 5.2.4 P2 — the workflow declares workflow_dispatch, or it cannot be branch-tested at all.
grep -q 'workflow_dispatch' ".github/workflows/$DISPATCH" \
  && echo "P2: OK" || echo "P2: NO-WORKFLOW_DISPATCH"

# 5.2.5 P3 — you are on a lane/2 branch, not integration and not main.
case "$BR" in lane/2/*) echo "P3: OK" ;; *) echo "P3: WRONG-REF" ;; esac

# 5.2.6 P4 — record whether the workflow binds a production environment. This decides how
#        the run's conclusion is read in 5.5, and it is a grep, not a judgment.
grep -qE '^\s*environment:\s*(production|.*name:\s*production)' ".github/workflows/$DISPATCH" \
  && echo "P4: BINDS-PRODUCTION" || echo "P4: NO-PRODUCTION-BINDING"

# 5.2.7 P5 — the branch is pushed, so the ref exists server-side.
git rev-parse HEAD "origin/$BR" | uniq | wc -l | xargs -I{} echo "P5-REFS-IDENTICAL: {}"
```

### 5.3 Dispatch

**Commands**

```bash
set -euo pipefail
# 5.3.1 Note the newest existing run id for this workflow BEFORE dispatching, so you can
#       tell your run apart from someone else's.
BEFORE="$(gh run list --workflow "$DISPATCH" --branch "$BR" --limit 1 \
  --json databaseId -q '.[0].databaseId // 0')"
echo "BEFORE_RUN_ID=$BEFORE"

# 5.3.2 Dispatch on YOUR branch. No other --ref value is ever correct in this runbook.
gh workflow run "$DISPATCH" --ref "$BR"

# 5.3.3 Capture the new run id.
RUN_ID="$(gh run list --workflow "$DISPATCH" --branch "$BR" --limit 1 \
  --json databaseId -q '.[0].databaseId')"
echo "RUN_ID=$RUN_ID"
[ "$RUN_ID" != "$BEFORE" ] && echo "NEW-RUN: OK" || echo "NEW-RUN: NOT-CREATED"

# 5.3.4 Watch it to completion. This blocks.
gh run watch "$RUN_ID" --exit-status; echo "WATCH-EXIT=$?"

# 5.3.5 Record the machine-readable outcome.
gh run view "$RUN_ID" --json conclusion,status,url,headBranch,workflowName \
  > "$T/dispatch-run.json"
cat "$T/dispatch-run.json"
CONCLUSION="$(gh run view "$RUN_ID" --json conclusion -q .conclusion)"
{
  echo "workflow=$DISPATCH"
  echo "ref=$BR"
  echo "run_id=$RUN_ID"
  echo "expected=$EXPECT"
  echo "actual=$CONCLUSION"
  echo "url=$(gh run view "$RUN_ID" --json url -q .url)"
} | tee "$T/dispatch.txt"
```

### 5.4 Read the result

**Commands**

```bash
set -euo pipefail
# 5.4.1 The verdict. Two strings only.
if [ "$CONCLUSION" = "$EXPECT" ]; then echo "DISPATCH_MATCH"; else echo "DISPATCH_MISMATCH"; fi

# 5.4.2 The production safety assertion. A lane-branch run that binds production and
#       concludes success means the environment policy of Sec 33.4 (L2887-2912) is not in
#       force. That is a P0 finding and is never a green test.
if grep -qE '^\s*environment:\s*(production|.*name:\s*production)' ".github/workflows/$DISPATCH" \
   && [ "$CONCLUSION" = "success" ]; then
  echo "PROD-POLICY: BREACH"
else
  echo "PROD-POLICY: OK"
fi
```

**Acceptance criteria**

| # | Criterion | Proving command | Unambiguous correct output |
|---|---|---|---|
| 05-A | Right repo, right ref, dispatchable workflow | steps 5.2.3–5.2.5 | exactly `P1: OK`, `P2: OK`, `P3: OK` |
| 05-B | Branch is published | step 5.2.7 | exactly `P5-REFS-IDENTICAL: 1` |
| 05-C | A new run was created by your dispatch | step 5.3.3 last line | exactly `NEW-RUN: OK` |
| 05-D | Conclusion equals the card's expectation | step 5.4.1 | exactly `DISPATCH_MATCH` |
| 05-E | No production-policy breach | step 5.4.2 | exactly `PROD-POLICY: OK` |
| 05-F | Evidence recorded for the PR body | `test -s "$T/dispatch.txt"; echo $?` | exactly `0` |

**SELF-VERIFY**

```bash
set -euo pipefail
{
  if [ "$(grep '^DISPATCH: ' "$T/card.txt" | cut -d' ' -f2-)" = "NONE" ]; then
    grep -q '^DISPATCH_NOT_APPLICABLE' "$T/dispatch.txt" && echo "05 ALL PASS (NOT APPLICABLE)" || echo "05 FAIL"
  else
    [ "$(grep '^expected=' "$T/dispatch.txt" | cut -d= -f2)" = "$(grep '^actual=' "$T/dispatch.txt" | cut -d= -f2)" ] \
      && echo "05-D PASS" || echo "05-D FAIL"
    test -s "$T/dispatch.txt" && echo "05-F PASS" || echo "05-F FAIL"
  fi
}
```

Correct output: either the single line `05 ALL PASS (NOT APPLICABLE)`, or the two lines `05-D PASS` and `05-F PASS`.

**STOP rule**

- `P1: WRONG-REPO` — you are pointed at a product repository. **Do not dispatch.** L2-RB-12, `DISPATCH-UNSAFE`. Rule 0.1.6.
- `P2: NO-WORKFLOW_DISPATCH` — the workflow cannot be branch-tested. Do **not** add a `workflow_dispatch` trigger to make it testable unless the task card's `FILES:` names that file and the card says so; adding a trigger changes the workflow's contract. L2-RB-13, `MIS-SCOPED-TASK`.
- `P3: WRONG-REF` — you were about to dispatch against `integration` or `main`. Stop, return to L2-RB-01.
- `NEW-RUN: NOT-CREATED` — the dispatch did not start a run. Do not re-dispatch more than twice. On the third failure, L2-RB-12, `DISPATCH-UNSAFE`, attaching `gh run list --branch "$BR" --limit 5`.
- `DISPATCH_MISMATCH` — go to L2-RB-10. Do not adjust `EXPECT` on the task card to match reality; the card is the specification and you do not edit it.
- `PROD-POLICY: BREACH` — **stop everything.** A lane branch reached production. This is a control failure in L5's environment configuration, not a bug in your file. L2-RB-12, `DISPATCH-UNSAFE`, condition line `lane-branch dispatch concluded success against environment: production`, citing §33.4 (L2887–2912) and §33.2 (L2854–2869). Do not retry, do not delete the run, do not proceed to L2-RB-06.

## L2-RB-06 — Test a workflow change safely — Tier 2, negative proof

**Size:** M **Depends on:** `L2-RB-05`
**Creates or edits in the repository:** nothing.
**Creates outside the repository:** `$T/neg-cases.txt`, `$T/negative.txt`.

A gate that has only ever been observed passing has not been tested. Spec §95.4 (L8697–8712) requires the checklist be "executed for real — including the negative tests"; §31.2 (L2787–2802, at L2791) applies the same logic to the verification contract itself: "A run in which the seeded defect passes is a **FAILED run**." Lane 2's Definition of Done rows DoD-03, DoD-04, DoD-07, DoD-08, DoD-10, DoD-11, DoD-12, DoD-13 and DoD-15 are all negative tests. This procedure executes the ones your task card names.

**Commands**

```bash
set -euo pipefail
# 6.1 Extract the card's negative cases. Format per line:
#     <case-id>|<workflow-basename>|<expected-conclusion>
sed -n '/^NEGATIVE-CASES:/,/^[A-Z-]*:/p' "$T/card.txt" \
  | grep -E '^[A-Za-z0-9_.-]+\|[A-Za-z0-9_.-]+\|(success|failure)$' \
  | tee "$T/neg-cases.txt"
grep -c . "$T/neg-cases.txt" | xargs -I{} echo "NEG-CASE-COUNT: {}"

# 6.2 Decide, mechanically, whether a negative case is required for this task.
#     It is required if and only if the branch changes a privileged workflow or a
#     workflow that emits a required status check.
git diff --name-only origin/integration...HEAD \
  | grep -cE '^\.github/workflows/(deploy-staging|deploy-production|migrate|restore-production|restore-test|build|ci)\.ya?ml$' \
  | xargs -I{} echo "GATED-FILES-TOUCHED: {}"

# 6.3 Execute each case. One run per case, watched to completion, recorded.
: > "$T/negative.txt"
while IFS='|' read -r CASE WF WANT; do
  [ -z "$CASE" ] && continue
  gh workflow run "$WF" --ref "$BR"
  NRUN="$(gh run list --workflow "$WF" --branch "$BR" --limit 1 --json databaseId -q '.[0].databaseId')"
  gh run watch "$NRUN" --exit-status >/dev/null 2>&1
  GOT="$(gh run view "$NRUN" --json conclusion -q .conclusion)"
  URL="$(gh run view "$NRUN" --json url -q .url)"
  if [ "$GOT" = "$WANT" ]; then R="NEG_OK"; else R="NEG_BROKEN"; fi
  echo "$R $CASE want=$WANT got=$GOT run=$URL" | tee -a "$T/negative.txt"
done < "$T/neg-cases.txt"

# 6.4 Verdict.
if [ ! -s "$T/neg-cases.txt" ]; then
  echo "NEGATIVE_NOT_APPLICABLE no cases on the card" | tee -a "$T/negative.txt"
elif [ "$(grep -c '^NEG_BROKEN' "$T/negative.txt")" -eq 0 ]; then
  echo "NEGATIVE_PASS" | tee -a "$T/negative.txt"
else
  echo "NEGATIVE_FAIL" | tee -a "$T/negative.txt"
fi
tail -1 "$T/negative.txt"
```

**Acceptance criteria**

|---|---|---|---|
| 06-A | Every case behaved as the card declared | `grep -c '^NEG_BROKEN' "$T/negative.txt"` | exactly `0` |
| 06-B | Verdict line | `tail -1 "$T/negative.txt"` | exactly `NEGATIVE_PASS` **or** exactly `NEGATIVE_NOT_APPLICABLE no cases on the card` |
