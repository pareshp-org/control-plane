# manual/ — Consolidated Round-2 Deep Review

**Scope.** All 13 files in `manual/` (00–11 plus 99-HARDENING). No manual/ file was reviewed in round 1, so this is the whole picture for the directory.

**Question asked.** Could a Sonnet-4.6-class agent with no repo context be dropped into lane N with only these 13 files and start work correctly?

**Answer.** No. The directory is BLOCKED. Nineteen consolidated blocking defects, of which eight stop execution before the agent's first edit, on every task, in all five lanes simultaneously.

**Method.** 337 per-file findings from 13 reviewers, deduplicated to 63 consolidated defects (19 blocker, 16 major clusters, 18 minor). Eight of the most serious claims were re-verified by command against the live files and `MultiProduct_MasterSpec_v4.0.md`. All eight survive. None refuted.

## 3. Verdict

### BLOCKED.

A Sonnet-4.6-class agent dropped into lane N with only these 13 files **cannot start work correctly, and in several cases cannot start at all.** The failure is not marginal. Walking the agent's first hour:

1. **It cannot find its task.** manual/00 §9 — "run this now", the first command in the manual — resolves to the wrong file for all five lanes (V5), and its extractor returns nine truncated lines with no acceptance criteria even when handed a correct id (V6). For lane 4 no heading-based extractor can ever work, because `L4-06-tasks.md` has no task headings.
2. **If it finds one, the protocol rejects it.** manual/02's task-ID regex rejects every id the five lane packs actually issue (V1). STOP-01 fires before Step 1.2, on 100% of tasks.
3. **If it gets past that, it cannot escalate.** Every STOP path in nine of the thirteen files ends in `gh issue create --label`, and no label the manual uses is created by any task. manual/08's blocker heredoc cannot even be pasted.
4. **If it works anyway, it cannot verify.** All four `make` entry points are undefined (V4) — including the one manual/01 L1946 makes an operator do-not-dispatch condition, which on its own terms forbids dispatching any session in the programme.
5. **If it verifies, it cannot finish.** manual/10's G4 always prints STOP (V3), and §10.1 makes one false gate BLOCKED. manual/11's OB-10 always FAILs, so the agent could not have been onboarded in the first place.
6. **The guards that were supposed to catch all of this cannot fail.** manual/04's scope check always reports zero violations (V7); manual/06's regexes report FAIL on clean branches and PASS unconditionally for L4 (V8); seven more guards across 03, 05, 07, 08, 10, 11 fail open or pass vacuously. There is no negative test anywhere in `manual/`.
7. **And the one procedure that runs when things go wrong pushes to `integration`.** (V2, reproduced.)

Layered on top: five competing "verbatim" templates per artefact (B9), five STOP taxonomies with colliding numbers (B10), two mutually exclusive operating models (B11), a worked example that self-merges (B12), and a hardening file that is readable by every lane and hands them a working exploit (B19).

**The pattern worth naming.** These are not thirteen independently sloppy files. Each file is internally coherent and was written as though it were the only document the agent would read — manual/00, manual/01 and each lane pack each say so explicitly. Nobody owned the seams. That is why the same act (commit, PR, blocker, report, stop, stage) has three to five mandatory-and-exclusive forms, and why the entry document references none of its siblings while the production prompts reference the entry document not at all. The fix is therefore mostly not rewriting: it is **assigning one owner per artefact and making twelve files point instead of restate.**

**What is genuinely good, and worth preserving through the fixes.** The doctrine is right and unusually well-argued: evidence over assertion, exit codes over prose, "a check that cannot fail is not a check", additive-only paths, no-judgment task cards, the read ladder, the tripwire model, and manual/04's V-rule structure. manual/06's PR rejection table and manual/03's STOP taxonomy are the two best-engineered artefacts in the set and should win their respective contests. The defects are overwhelmingly in the *mechanics* — shell that does not do what its prose says — not in the thinking.
